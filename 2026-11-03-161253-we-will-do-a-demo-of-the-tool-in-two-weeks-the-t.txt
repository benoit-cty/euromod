  The index I'd suggest

  The idea is to start from EUROMOD 2024, let the agent find the 2025 law on its
  own, then compare its answer with EUROMOD 2025 and with OpenFisca 2025.

  ┌─────────────────────┬────────────────────┬──────────────────────────────┐
  │                     │ EUROMOD changed it │ EUROMOD kept it (~333 + VAT) │
  │                     │        (192)       │                              │
  ├─────────────────────┼────────────────────┼──────────────────────────────┤
  │ Agent: changed,     │ change found ✅    │ —                            │
  │ same value          │                    │                              │
  ├─────────────────────┼────────────────────┼──────────────────────────────┤
  │ Agent: changed,     │ wrong value        │ false alarm, or EUROMOD is   │
  │ different value     │                    │ wrong → check OpenFisca      │
  ├─────────────────────┼────────────────────┼──────────────────────────────┤
  │ Agent: unchanged    │ missed change      │ confirmed ✅                 │
  │                     │ (false negative)   │                              │
  ├─────────────────────┼────────────────────┼──────────────────────────────┤
  │ Agent: not found    │ corpus gap         │ corpus gap                   │
  └─────────────────────┴────────────────────┴──────────────────────────────┘

  The headline figures would be:
  - coverage: the share of parameters where the agent gives an answer backed by
    a quoted source;
  - change recall: how many of the 192 changes it finds with the right value;
  - precision: how many of its answers match;
  - disagreements: for each one, who is right after checking against OpenFisca.

  The best demo story is when the agent and OpenFisca agree and EUROMOD doesn't.
  We already have one: EUROMOD's 2025 income-tax thresholds are 1 € below the
  law, and the scoring is strict enough that this still shows up as a
  difference. Cost, time and CO₂ come from the existing impact command.

  What has to change first

  1. The test isn't blind today. The prompt shows the agent the latest EUROMOD
     value (prompts.py:137), which for FR is the 2026 row. For every parameter
     that hasn't changed since 2024, that is already the right answer. We need a
     "baseline 2024" mode that hides every value from 2025 onwards and compares
     against the 2024 value. This also affects the existing eval scores; the
     prompt says the value is out of date, but this would be worth fixing.
  2. We need a scorer that covers all parameters, not just golden cases. It
     would take the expected values from EUROMOD 2025 and OpenFisca 2025, reuse
     the existing scoring, and store results in eval.*.
  3. Mid-year changes. Housing benefits change in October and family benefits in
     April. EUROMOD stores some of these as a weighted average for the year, so
     the scorer must accept either the value on the reference date or that
     average. Otherwise about 60 correct answers would count as misses.
  4. Close corpus gaps. This is where the tuning time goes. In the golden set,
     16 of 52 FR cases had no corpus, and they are mostly revaluation decrees,
     orders and CNAF circulars. A first full run will list the acts the agent
     couldn't find; we ingest them and run again.
  5. Check the 71 OpenFisca links on changed parameters by hand before claiming
     "EUROMOD is wrong" in front of the team.
